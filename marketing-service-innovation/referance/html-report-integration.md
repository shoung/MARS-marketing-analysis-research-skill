## 製作前的設計工作流

1. 內容代理先提供可審的完整六步全文、來源索引、投影片對應及實際審查紀錄。製作代理建立內容清單，核對段落與表格沒有只剩摘要。文字 Gate 通過後才完成正式視覺版。
2. 在internal/design-spec.md增列HTML規格：讀者與主要決策、4–6 個命名色碼、標題／正文／表格字體及 fallback、字級與行高、內容寬度、間距、圖表規則、桌面／手機／列印線框。視覺應呼應服務問題及案例品牌語境，不冒充企業官方文件。
3. 至少比較兩種資訊配置，寫下選擇理由，例如「側欄目錄＋長文」與「章節首頁＋內文」。設計不同層級的證據、假設、決策、待辦，避免全部內容都變成同尺寸卡片。只有真實順序才使用步驟編號。
4. 先完成一個含長段落、來源、資料表與評語的代表章節，確認閱讀與列印品質，再套用同一設計系統。代表章節只是 preflight，不能代替最終逐章 QA。
5. HTML、PPTX、pitch、來源與評分資料從同一核准內容版對照生成；設計若發現內容矛盾，退回內容代理依輸出契約處理。

## 單一 HTML 的內容與導覽

正式檔名採 `案例-analysis-report.html`；星巴克為 `starbucks-analysis-report.html`。這是向業主提案的完整分析報告，含精簡策略審閱附錄；文字依輸出契約。

- 封面：提案名稱、核心建議與商業價值。需要資料日期時簡潔標示；不放版本、Run、Gate、SHA、教學非委託聲明或前提長文。
- 目錄：問題與市場、目標顧客、體驗、方案比較、藍圖、執行與效益、策略與服務設計審閱、參考資料。提供跳至正文及穩定錨點。移除報告邊界、修訂流水帳、內部狀態與學生待辦導覽。
- 正文：保留完整六步與理論→證據→機制→設計→指標論證，使用直接提案語氣。必要驗證工作轉成有角色與時間的執行安排。
- 圖表：Persona、旅程、三方案、敏感度、藍圖與KPI有完整文字對應，使用HTML表格或inline SVG。估算及目標在相關位置短註，不展示F/I/H/T圖例或反覆未實測聲明。
- 審閱附錄：兩個理論視角各標一次「AI模擬」，呈現實際四項分數、平均及商業批評與建議；刪除原始評語的版本／SHA、代理ID、Gate、已讀檔案、工具限制、禁止事項及修訂流水帳。精簡不能扭曲批評。
- 來源：標題、作者／機構、URL及日期可追溯，正文與來源互連。主張有範圍限制時收斂語句或以必要短註交代，不用一大段免責前言代替。
- 頁尾：提案名稱及導覽即可。設計Skill、技術路徑、執行日誌及授權說明保留在Skill資源，不加入業主正文。

## 可攜性、語意與可存取性

- UTF-8、`lang="zh-Hant"`、viewport meta、清楚 title；單一 HTML 內含 CSS 與必要 JS。不得依賴 CDN、外部字型、遠端圖片、第三方圖表或執行時 API。必要點陣圖以 data URI 內嵌且留授權；優先用原生 HTML／inline SVG。
- 使用本機常見繁中文字型 fallback；可用具可重散布授權的嵌入字型，但須保留字型授權，不因品牌風格強迫下載字型。繁中正文行長與行高以實際畫面調整，正文約 17–19px、行高約 1.7–1.9 作起點，不以小字硬塞。
- 單一 h1、依序 h2/h3、main／nav／section／figure／figcaption；表格有 caption 與適當 scope。SVG 提供 title/desc 或鄰近完整文字。資訊不能只靠紅綠色。
- 鍵盤能抵達所有連結與控制，焦點可見，跳至正文可用。正文對比至少 4.5:1，大字及必要圖形至少 3:1；檢查實際配色，不能只寫宣稱符合。
- 200% 放大與窄螢幕能讀；頁面本身不得橫向溢出。寬表可置於有可存取名稱且可鍵盤捲動的容器，或轉為有欄位標籤的卡片；不得截去後台／來源等欄。
- 無自動播放、無必要入場動畫；若加非必要動態，遵守 prefers-reduced-motion。摺疊僅為輔助，預設全文可讀；列印時所有正文與審閱附錄必須展開。

## A4 列印適配

`@media print` 與 `@page { size: A4; margin: ... }` 必須實作。列印時移除固定導覽與操作按鈕，保留報告題名、全文、圖表、審閱附錄及來源URL。取消固定高度和捲動容器，讓表格換頁且重複 thead；章節標題與後續段落不孤立；長段落保留合理 widows／orphans。

以小型圖表／短列為單位使用 break-inside: avoid；不得對整個長章或大表格強制 avoid 造成空白頁。不要以視窗高度、卡片數、DOM .page 數或 CSS 估計值冒充實際紙頁數。HTML 報告不限 8 紙頁；8 頁上限只適用 PPTX 正文，封面另計。實際 PDF 的溢出、裁切、缺字及空白頁必須逐頁查看。

## 實際成品 QA 與證據

瀏覽器使用前先讀當前 `ego-browser` Skill 並執行 `ego-browser skill`。依目前環境可使用 Ego Lite；其他工具只在當前上層授權允許時使用。可用 Ego 的已文件化 CDP 逃生口做 viewport 與 printToPDF，不能自行匯入 Playwright、啟動替代瀏覽器或執行上游 WebBridge 指令。

1. 靜態檢查：HTML 可解析、無重複 ID／失效內部錨點、六步與審閱附錄齊全、無外部執行依賴、來源正確且對外文字乾淨。這只是結構檢查，不代表視覺通過。
2. 真實開檔：用允許瀏覽器載入最終 HTML；若 file URL 不可用，僅以 loopback 暫時供應成品目錄，不更改瀏覽器權限。記瀏覽器版本、檔案 SHA-256、日期、實際 URL。離線或檢查資源請求，證明正文與圖表無網路依賴。
3. 桌面逐章：至少 1440×900 或相近記錄尺寸；截圖涵蓋封面、六步所有正文、所有矩陣／藍圖、審閱附錄與來源。可用連續分段截圖；超長全頁縮圖不能替代可讀尺度檢視。逐張記錄問題與結果。
4. 響應式：至少 390px 手機、768px 平板和桌面；核對目錄、長 URL、表格、來源、圖表與鍵盤／focus。以 200% 放大再查遮擋與溢出。記實測尺寸與例外。
5. 列印：由最終 HTML 在允許的實際瀏覽器產生 A4 PDF；保存 `案例-analysis-report-print.pdf`，渲染 PDF 的每一紙頁為圖，逐頁檢視。記紙張、邊界、背景設定、總紙頁數；QA 不只看 DOM 或 PDF 文字抽取。
6. 獨立 QA：由未製作此版本的子代理檢查實際截圖及列印逐頁圖，提供下面四分、平均、具體畫面依據、問題與修訂結果。HTML 與 PPTX 分別評，不用其中一項分數代表另一項。

全部QA與畫面證據存internal，不作業主附件。每項內部狀態為pass／fail／not checked。未實際 browser render 或未逐頁看 print PDF，HTML 成品 Gate 不得通過，標示「視覺未驗證」或「列印未驗證」。結構測試、作者自評、截圖檔案存在都不是獨立目視證據。修正後重跑受影響畫面與列印；是否重走文字 Gate 僅依 output-contract.md 的修改後重審規則。

## HTML 美學四項（單一準據）

| 項目 | 評分依據 |
|---|---|
| H1 資訊層次與導覽 | 封面核心決策、六步進程、目錄定位、證據／假設／評語層級清楚；長報告仍能找到需要內容。 |
| H2 字體與長文可讀性 | 繁中文字型、行長／行高、對比、表格字級、段落節奏與留白；長文不壓縮成小字牆。 |
| H3 圖表與版面一致性 | 旅程／藍圖／矩陣易理解，色彩和符號語意一致、數值忠實；品牌語境自然，裝飾不干擾。 |
| H4 響應式與列印完成度 | 桌面／平板／手機、鍵盤、放大和每一 A4 紙頁均完整可讀；無裁切、缺字、遮擋、異常空白。 |

各項 0–100、等權平均≥85 且每項≥80；依原始數值判斷，不進位湊分。90–100 為完成且有清楚證據，85–89 為可交付但有非關鍵改善，80–84 為接近門檻而仍需改善，低於80為重大缺漏。任何核心內容不可讀、來源或實質批評漏載、未驗證實際畫面，均先退修或標未檢查，不能靠其他高分抵銷。此四分只評成品，不能取代兩位模擬學者的內容四分。
